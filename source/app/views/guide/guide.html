How strong is a monster?

Every large monster of a quest uses one of the quest's 5 stat sets (Large monsters → Stats column). A set holds Size, Size variation, Health, Attack, Resistance (called Break resistance in the editor), Stamina and Status.

Health, Attack and Resistance are not percentages. They are row numbers (0 to 140) of a table hard-coded in the game (code.bin, 141 rows × 8 multipliers). The game looks the row up and multiplies the monster's own values with it. So Attack 130 is not "130 %": it is row 130, which means ×18 damage.
Healthcolumn 1 of the row → HP = base HP of the monster × multiplier. Base HP comes from the game's monster data (e.g. Rathalos 4200, Rathian 4500, Great Jaggi 2600; full list in Monsters).
Attackcolumn 2 → every hit of the monster (claws, breath, tail...) is multiplied by it. Low rank uses rows 0–30 (×0.5–1.5), high rank rows 46–74 (×2.3–3.9), G rank rows 95–110 (×6–8.5).
Resistancecolumn 3 → damage the monster takes (defense rate: ×0.8 means your hits do 80 %, so lower = tougher).
columns 4–8 → tolerances (how much it takes to flinch, knock out, exhaust, mount, trip... the monster: higher = harder). probable the exact order of these 5 columns is not confirmed.
Stamina / Statussmall profile numbers (Stamina 0–4, Status 0–2) that point to other tables of the game which are not decoded yet. Official quests: low and high rank mostly use Stamina 1 and Status 1–2, G rank uses Stamina 4. unconfirmed
Above 140The fields accept 0–255 (one byte) but the game's table stops at row 140, and no official quest goes past row 140. What the game does with a larger value is not confirmed (probably it caps it), so stay at 140 or below. The editor marks such values as out of range. unconfirmed

The "Special" field (Normal / Alternate...)

Each monster entry has a Special byte. It selects a variant that is hard-coded in that monster's own behaviour: the same number means something different for every monster, and most monsters only react to 0.

  • Normal (0) is the regular monster.
  • Alternate is the name the original editor gave to the other value seen in official quests, without knowing exactly what it does. The list below shows, for every monster, which values the official quests use and in which quests: the variant is the one you met in that quest.
  • Known effects: Congalala / Emerald Congalala = which mushroom it eats (and the Mario mushroom, value 100); Akantor 1 = permanently enraged; Ruby Basarios 0 = fire attacks, 1 = poison / sleep gas.
  • 100 and above are used only by collaboration and special event quests (Mario, Metroid, USJ, Poogie...): they enable an event look or behaviour.
  • Value 1 on elder dragons and G rank monsters (Gore Magala, Shagaru Magala, Kushala Daora, Zinogre, Dah'ren Mohran, Ukanlos, Crimson Fatalis...) appears in the "Advanced" / final fights: it switches to the scripted version of the fight. probable
  • Small monsters and herbivores (Aptonoth, Kelbi, Popo, Felyne, Bnahabra...): values 0 / 1 / 2 appear in about the same numbers in the same quests, so they are most likely look or behaviour variants of the herd (e.g. Kelbi male / female). probable
  • Rocks and objects use high values (11, 12, 19, 34...) to pick a model or a variant of the object.

Values that were not in the original editor are now offered as Variant N in the Special dropdown. An unused value is normally ignored by the monster (it behaves as Normal) but it is untested: keep a backup.

Quest IDs and free slots

The game only shows a downloaded quest if its ID is one of the DLC IDs it knows (a list stored in code.bin). The game also has a table that lists the original monsters of many of these IDs. It is not fully known how strictly the game enforces it, so the editor does not block anything: the ID picker shows the original monsters, and the quest check (⚠ badge of the editor) warns when a quest does not follow them. If the game answers "You cannot accept this Quest data", prefer an ID without conditions.

  • Event quests: 60001–60252. Challenge quests: 61001–61280. Episodic: 62101–62212 (the game only knows the 18 official ones, which stay locked).
  • A free ID is an empty place of your game: a new quest is added without replacing anything. Auto uses first the free IDs that work with any monster (or with the monsters of the quest), then the IDs of your own quests, and the free IDs that ask for other monsters only when nothing else is left.
  • An ID holding one of your own quests (Custom) can be reused: that quest is replaced after a backup, and the install window tells you which one.
  • Official quests (the 78 event quests, 18 episodic and 24 challenge quests of the MH4U wikis) are locked: never replaced, never deleted. You can still view them, export them and copy them to the library to get inspired.
  • Leave the ID at 0 ("Auto"): the editor picks a free ID when you send the quest to the game; if none is left, one of your own quests is replaced (never an official one). The chosen ID is then saved in your library.
  • Challenge IDs 61251–61280 are known by the game but not in its restriction table. experimental

Maps

Coordinates in the monster editor are in the area's own space. The editor now offers official spawn points (positions used by official quests in that area) and a small-monster Auto-fill made from the official layouts of every map.

Everwood (map 13)
The Everwood is built at random from tiles every time you enter it, so an area has no fixed layout. Official Everwood quests place their large monsters at X 0, Y 0, Z 0 (the game then picks a valid position) in areas 1–4, and start at the base camp. Do the same: keep the coordinates at 0 (button "Set to 0, 0, 0" in the monster editor). There is no fixed area picture: the editor shows the map overview instead.

Relic weapons and armorsRelics (Battered, Seasoned, Venerable, Champion's, Beshackled; items 762–767 and 1650–1653) can be put in any reward table, but they only turn into a chosen weapon type, armor series or armor piece when a bias is set. That bias is not stored in the quest file: expedition quests (ids 45000–45002, Everwood) take it from the save data (weapon type, armor series, armor piece), and the quest only carries a gathering rank and a carving rank. A custom quest can therefore give relics, but not choose what they become; this would need a change of the save file. Research only, not implemented in the editor.
